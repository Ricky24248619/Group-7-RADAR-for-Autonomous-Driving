# EXP-0034 — Density-matched LiDAR control on TruckScenes object support

- Date: 29 September 2026.
- Owner: Fatima Sher; reviewer Kelsey Chen. Story FA-S3-1, Epic C.
- Question: record 0016 reports 2,118 of 2,309 released box observations LiDAR-supported at 150-400 m against 350 for radar, and record 0017 puts the recorded radar boundary near 189.5 m, so range does not explain the gap. How much of it is explained by point count alone?
- Method: per frame, keep a uniformly random subset of the LiDAR returns the size of that frame's radar returns, then recount support under the unchanged definition. Computed from the committed paired-support evidence rather than the raw release: keeping `n` of `N` returns and asking whether at least one of a box's `k` returns survives is the hypergeometric distribution, and both inputs are already committed — in-box counts in `object_counts.csv`, total returns per frame per modality in `sample_channel_ranges.csv`. The expectation is therefore exact rather than estimated, and it is consistent with record 0016 by construction because it uses the same counts that produced it. Two hundred seeded draws are reported alongside; the exact value falls inside the 5th-95th percentile band in every band and margin.
- Result record: 0041. [Evidence](../docs/evidence/truckscenes/density-matched/).
- Measured: 389 frames, every one reduced by matching, median 77.9 LiDAR returns per radar return. At 150-400 m and margin 0, density-matched LiDAR support is 290.0 of 2,309 (12.6%) against 2,118 (91.7%) for the full cloud and 350 (15.2%) for radar. At margin 0.5 the same band gives 358.7 (15.5%) matched against 2,283 (98.9%) full and 646 (28.0%) radar.
- Principal finding: beyond 50 m the LiDAR support advantage does not survive an equal point budget, at either margin. Most of the long-range gap in record 0016 is explained by point count alone.
- Margin sensitivity changes the short-range reading, and the honest version is the weaker one: at margin 0 the matched LiDAR still leads radar below 50 m (7,901.5 against 6,753), but at margin 0.5 it does not (8,425.2 against 8,922). The close-range advantage is therefore not robust to the sensitivity check and should not be reported as a finding.
- Limitations: geometric support, not detection recall or mAP; no model is run and no detector is scored. Uniform random thinning is one null model — a genuinely lower-resolution sensor would thin structurally rather than at random — so this bounds how much of the gap arithmetic explains rather than predicting how a cheaper sensor behaves. Per-box draws treat boxes within a frame as independent, which affects the reported spread but not the exact expectation. Inherits every limitation of record 0016, including LiDAR-based annotation selection and repeated observations across scenes. Recorded radar returns stop near 189.5 m, bounding any statement about bands beyond it.
- Validation: 84 tests across the sampling module and the runner, including the probability checked against hand-worked closed forms and against a brute-force simulation, monotonicity in both arguments, the edges where subsampling cannot change anything, and agreement between the exact value and the seeded draws. Full dependency-light suite and both existing validators pass. Two defects were caught by these tests during development: a generator seeded per box rather than per frame, which collapsed the reported spread, and a share computed from an unrounded value while its count was rounded, which made the output internally inconsistent.
- Reproducibility: outputs carry no timestamp and use LF endings. Regenerating on macOS reproduced the Linux run byte-for-byte, so the reported numbers are not machine-specific. The manifest records input SHA-256 hashes, seed, draw count and limitations. No dataset on disk is required.
