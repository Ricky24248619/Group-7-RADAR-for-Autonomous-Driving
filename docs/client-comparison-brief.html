What do radar and LiDAR see at long range?

Our current mini-dataset evidence does not justify replacing LiDAR with radar for object coverage.

Follow-up finding: all recorded radar returns end near 189.52 m from each sensor. The maximum observed labelled object range is 229.42 m; 150-400 m was a storage bin. Within 150-180 m, LiDAR/radar geometric support remains 93.16% versus 22.10%. This supports a dataset-specific coverage finding, not a universal long-range detection ranking. Read the deeper evidence audit.

We compared the same labelled objects using all six radar and all six LiDAR sensors. The completed experiment covers 389 samples, 25,117 box observations and 1,092 tracked instances across ten scenes. LiDAR points were corrected for ego motion using their individual timestamps.

What these numbers mean: the share of labelled 3D boxes containing at least one sensor return. They are geometric support figures, not detector accuracy. Labels were created using LiDAR, so objects absent from those labels are outside this comparison.

Beyond 150 m, radar supports 350 of 2,309 observations; only 57 have at least three radar returns. LiDAR supports 2,118. Taking either sensor suite adds six observations to LiDAR, changing support from 91.73% to 91.99%. This is not a learned fusion score.

2. Motion correction changes the apparent benefit

On the same 25,117 observations, a single transform per LiDAR scan produces 185 apparent radar-only observations. Correcting each point's acquisition time reduces that to 39. LiDAR-supported observations increase from 22,650 to 24,616.

Expanding box faces by 0.5 m reduces radar-only observations to three overall and zero beyond 150 m. Expanded boxes can include background. This is a sensitivity test showing why we cannot turn the small radar-only count into a robust fusion-performance claim.

3. A paired example the team can explain

The first car beyond 100 m in fixed scene/time/annotation order has 37 LiDAR returns and zero radar returns in the exact box. This is one illustration, not a representative average. The rectangle is a human-labelled box, not a model prediction.

Recorded radar range limits the comparison

All 2,400 radar keyframes were checked. The cause of the common boundary remains unconfirmed. It must not be interpreted as an intrinsic hardware limit. The LiDAR support difference persists in all nine scenes containing distant labels and with one observation per tracked instance.

What should happen next?

  1. Reconcile LiDAR preprocessing. Our radar counts match all 25,117 publisher counts. LiDAR counts match exactly in only 4,164 cases. Point-wise correction improves support but does not reproduce the publisher's full LiDAR counting process.
  2. Run compatible radar-only and LiDAR-only detectors on the same held-out samples. Keep task, classes, evaluator and temporal history matched. Then report detection precision/recall and scores by range.
  3. Test radar's additional value on moving and distant vehicles. Compare the two single-modality models with a documented combined model. Velocity quality and weather robustness remain open questions.

Dataset roles: TruckScenes is our paired urban/trucking comparison. GOOSE provides off-road semantic analysis; its earlier partial model run is not a completed benchmark. TruckDrive now has a verified paired-scene run, reported at the top of this briefing.

Scope and exclusions: one sample exceeds the 50 ms sensor timing gate; ten more have insufficient continuous poses over full scans. All eleven are excluded from both modalities. No target-motion or additional cabin-motion correction is claimed. Observations repeat objects over time, and ten scenes do not establish general weather robustness.

Model resource status: both official K-Radar model downloads returned Google Drive quota-exceeded pages today. No checkpoint or K-Radar inference was completed. Its first sample sequence is listed at 219 GB and was not downloaded. Buying compute does not resolve this access/compatibility gap.

Validation: seven focused tests pass in the raw runtime; the full lightweight suite passes 167 tests with three optional tests skipped. Geometry matches the official devkit on 50 randomized cases. Detailed tables, source hashes and exclusions are saved in the repository.
